## 遇到了什么瓶颈

Prefix QKV 在 backbone 中仍包含归一化、BF16 GEMM、类型转换、旋转和 Q/K/V 分发，外围操作存在融合机会。

## 当时看到了哪些证据

Target 内已有可复用 RMSNorm；源码要求归一化后先舍入、投影后再舍入。真实 18 层的布局与调用次数已明确，不能直接把另一个调用点的局部收益套到这里。

## 提出了什么假设

保留 BF16 QKV GEMM，用已有 RMSNorm 加一个 native cast/rotation/scatter pass 减少中间遍历和启动。

## 执行了哪些命令、做了什么改动

实现 prefix QKV wrapper，运行 `python -m lab.pi05.rtx5090_prefix_qkv --seed 42`；检查实际层 0/9/17 的 Q/K/V 和归一化结果，测 18 次调用图，再由 `7085a4b` 切换部署并运行官方 parity 与延迟命令。

## 得到了什么结果

所选层逐位一致，局部每次 137.960 → 58.0524 µs，按 18 次外推 1.4383 ms。官方 action cosine 0.9999866853、rel_rms 0.00516067；部署中位数 35.3236 → 33.9966 ms。无编译器环境的 CPU 声明也通过。

## 为什么保留、回退或继续调查

保留。该轮部署差额 1.3271 ms 大于单次内部波动；全 18 层、10 次 denoise 和 BF16 workload 保持原值。累计改善不代表优化耗尽，后续仍应基于新 profile 定位剩余热点。
